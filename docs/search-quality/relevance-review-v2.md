# Полный аудит составных вопросов и кандидат уточнения условий

## Ревизия оценок v2

Перечитаны источники для оставшихся восьми составных вопросов. Ревизия `relevance-reviewed-v2.json` охватывает все 12 составных вопросов прежних пилотов и отдельный вопрос про игру: **13 вопросов, 40 оценок источников**. Первые пять случаев скопированы из v1 без изменений. Обе версии и прежние оценки по конкретным главам сохранены.

Для восьми добавленных вопросов две части ответа действительно различны: гибкая сабля и силовой винден; свой и чужой батман; опора ног и руки; два варианта укола; координация мячами и темп партнёра; ошибки ученика и монитора; время выбора и подстройка темпа; ветка угрозы и сигнал задней ноги. Требование покрыть обе части осталось.

Добавлены подтверждённые альтернативы: конспект механики входа, нагрузочная проверка баклера на 1708,9 секунде, конспект парной связки, прогрессия мячей в конспекте и упражнение на запуск рук задней ногой на 748,96 секунде. Отдельная сложная ловля не заменяет описание прогрессии; краткая связка dritto не заменяет объяснение непрерывного контроля клинка.

На захваченном индексе три из 12 составных вопросов полностью покрывают проверенные требования, шесть — половину, три — ни одного проверенного аспекта. Единственное изменение относительно прежнего требования двух глав связано с уже описанным вопросом про проигранное соединение. Новые альтернативы не улучшили оценку текущей первой пятёрки. Неразмеченные результаты остаются неизвестными.

Это изменение и расширение оценки, **не улучшение алгоритма**. Снимок выдачи и его хеш сохранены в [результатах v2](relevance-review-v2.json). Он относится к индексу на момент захвата, а не ко всем будущим пополнениям архива.

## Проверка полноты карточек

Прочитана 21 уникальная карточка глав, участвующих в оценках. Основные условия для батмана без контакта, переноса после чужого батмана, контроля баклером, виндена и упрощения решений уже представлены. Поэтому нельзя объяснять все промахи отсутствием этих условий.

Для трёх глав меча и баклера подготовлен отдельный кандидат из девяти дополнительных полей:

- Стойка: проверка обеих ног после шага, положение задней стопы/колена, ограничение удлинения базы.
- Шаффл: сбор ног перед раскрытием, обмен опорой пятка/носок, ошибки задней ноги и длины стойки.
- Игра: вход в квадрат, зачёт только после выхода без попадания, удар ниже колена без силы из условных ножен.

Каждое поле подтверждено точной цитатой тезиса. Кандидат проходит тот же dry-run валидатор, что обычные карточки; отчёты, тезисы и таймкоды не менялись.

## Новый прогон кандидата

После фиксации кандидата подготовлены девять новых формулировок: шесть для уточняемых глав и три для неизменённых контрольных глав. Формулировки новые, темы известны автору; это не независимая человеческая оценка. Реестр и хеш кандидата зафиксированы до измерения.

| Область | Принятые карточки | Кандидат |
|---|---:|---:|
| Запись | 8/9 | 8/9 |
| Коллекция | 8/9 | 8/9 |
| Архив | 7/9 | 7/9 |

Индивидуальных потерь нет, но прирост Hit@5 равен нулю. Gzip core вырос на 226 байт. Целевой прирост в коллекциях не достигнут, поэтому **кандидат не принят**. Полный старый набор регрессий повторно не запускался для его продвижения: нулевой результат нового прогона уже исключил включение. Текущие карточки восстановлены побайтно, индекс пересобран.

За время работы в архиве появилась новая запись; парное сравнение кандидата использует свежий индекс из 159 записей в обеих конфигурациях. Эти числа не сравниваются напрямую с более ранними метриками другого состава архива.

[Машинная сводка кандидата](conditions-candidate.json). Новые вопросы после прогона раскрыты и не считаются свежим holdout следующей настройки.

## Воспроизведение

```powershell
node scripts/search-enrichment/freeze-relevance-review-v2.mjs --dry-run
$env:RELEVANCE_VERSION='v2'
$env:RELEVANCE_REVIEW='1'
node node_modules/vitest/vitest.mjs run scripts/search-enrichment/relevance-review.test.ts --pool=threads --maxWorkers=1 --no-file-parallelism
node scripts/search-enrichment/evaluate-relevance-review.mjs
Remove-Item Env:RELEVANCE_VERSION
Remove-Item Env:RELEVANCE_REVIEW

node scripts/search-enrichment/prepare-conditions-candidate.mjs
node scripts/search-enrichment/conditions-run.mjs
```

Runner проверяет хеш кандидата, импортирует с dry-run и восстанавливает исходный sidecar в finally. Если файл изменён вне эксперимента, чужая версия сохраняется, а исходная копия записывается отдельно для восстановления. Старые ревизии оценок и результатов не перезаписываются.

## Состояние плана

Проверки альтернативных источников и полноты условий для текущего набора завершены. Простые перестановки, разбиение запросов и этот кандидат условий не приняли. В рабочей версии остаётся ранее подтверждённое улучшение на 113 главах.

Следующий приоритет — обкатать готовый workflow поисковой подготовки в обычной обработке двух новых записей и одной изменённой, затем завершить интеграцию основного скилла. Улучшение составных вопросов остаётся отдельной нерешённой задачей; факт завершения диагностики не означает, что поиск научился собирать полный ответ.
