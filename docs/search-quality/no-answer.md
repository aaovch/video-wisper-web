# Проверка слабых совпадений и числовых ограничений

## Решение

Включено точное сопоставление числовых токенов запроса (две и более цифры, как в существующем токенизаторе). Год или идентификатор нельзя заменить похожим числом через prefix/fuzzy или проигнорировать через semantic OR. Число должно входить в совпавшие термины каждого результата. Фильтр действует вместе с ограничениями области и до выбора уровня поиска. Обычные слова могут по-прежнему исправляться: «турнр 2026» находит «турнир 2026».

Это ограниченное правило, не классификатор отвечаемости. Оно не понимает фантастичность телепортации или смысл числительных, записанных словами. Не интерпретирует диапазоны и даты; не индексирует таймкоды как отдельные поисковые поля. Поиск по неполному году теперь требует полного числа. Полноценная проверка того, отвечает ли текст на вопрос, остаётся нерешённой.

## Отклонённый эксперимент

Проверен порог 35% совпавших исходных слов запроса в одном документе (с учётом допустимых опечаток, без добавленных синонимов). Он сократил постороннюю непустую выдачу, но убрал семь прежних Hit@5 внутри записей на основном фехтовальном наборе. Среди потерь — вопросы о преждевременном блоке и упражнении против реакции на каждое движение. Порог не включён. 50% на отрицательном наборе не лучше 35%, поэтому расширенный положительный прогон для него не проводился.

Для воспроизведения отклонённого варианта есть `VITE_SEARCH_EVIDENCE_FLOOR=0.35`; обычное значение — 0. Для отключения принятого числового правила при сравнении — `VITE_SEARCH_NUMERIC_EVIDENCE=0`. Это флаги сборки, не пользовательские настройки интерфейса.

## Проверки

Восемь синтетических невозможных запросов проверяются в коллекции NoName и архиве: четыре прежних вопроса и четыре новых без номеров. Непустая выдача считается ложным совпадением; сайт не генерирует текстовые ответы. Это небольшой искусственный набор, не оценка точности на реальных пользовательских запросах.

Подробные выдачи: [no-answer-results.json](no-answer-results.json). `floor=off` означает прежнее поведение, `floor=0` — только числовое правило, остальные значения — дополнительные пороги покрытия.

```powershell
$env:NO_ANSWER_EVAL='1'
node node_modules/vitest/vitest.mjs run scripts/search-enrichment/no-answer.test.ts
Remove-Item Env:NO_ANSWER_EVAL
```

Unit-регрессия проверяет несуществующий год, неполный год, вымышленный номер, существующий год, опечатку в слове рядом с правильным годом и обычный вопрос с годом. Основной и дополнительный фехтовальные наборы повторяются отдельно.

## Результаты принятого правила

- Основной набор: 228 сценариев, одинаковые fixture/index hashes с baseline; положительные выдачи, matchKind и fallback не изменились. Непустых отрицательных выдач 15 → 0 из 20.
- Набор сабли/баклера: 68 сценариев, положительные выдачи не изменились; ответ про батман остался первым в архиве.
- Расширенный отрицательный набор: 14 → 8 непустых выдач из 16. Все четыре новых вопроса без чисел по-прежнему находят посторонние материалы в обеих областях. Поэтому улучшение относится именно к явно указанным числам, а не к общему распознаванию несуществующих тем.
- Более строгие пороги 35% и 50% дают 4/16, но 35% теряет семь полезных сценариев; этот компромисс отклонён.

Сохраняемые рабочие прогоны: `.codex/search-fencing/ranking-numeric.json`, `ranking-numeric-holdout.json`; сравнение с `ranking-aliases*.json`. Отрицательные результаты выше сохранены в версионированном JSON рядом с документом.

Финальная проверка: 51 обычный тест прошёл; три экспериментальных теста штатно пропущены в общей команде (fencing и no-answer выполнены отдельно). Проверка типов — 0 ошибок/предупреждений, production build успешен. В браузере на свежем preview коллекция «Алматы 2026» показывает «Ничего не найдено» для расписания турнира на Марсе 2099, а `winden` по-прежнему находит главу про виндены. Ошибок браузера нет. Изменение включено локально; публикация не выполнялась.
