# Перенос старых паролей в админку

До появления админки база доступа сохраняла только хеши паролей. Обновление
серверного кода само по себе не возвращает их текст. Для старых ключей нужен
отдельный перенос исходных значений из приватных записей владельца.

`server/restore-passwords.mjs` принимает JSON `{"passwords":[...]}` через stdin.
Сначала запустить без `--write`, обязательно с `--require-complete`:

```text
node server/restore-passwords.mjs <путь-к-существующей-access.sqlite> --require-complete
```

После успешной проверки передать тот же приватный JSON через stdin:

```text
node server/restore-passwords.mjs <путь-к-существующей-access.sqlite> --write --require-complete
```

Команда сопоставляет точный SHA-256 исходного пароля с уже существующим ключом.
Несовпадающие и отозванные значения игнорируются; мастер-ключ не импортируется.
`--require-complete` запрещает частичный импорт, если хотя бы один действующий
обычный ключ всё ещё не имеет доступного текста. Уже сохранённые значения
проверяются расшифровкой и сопоставлением хеша.

Перенос добавляет только зашифрованные значения в `saved_passwords`. Группы
доступа, прежние пароли, дополнительные разрешения, сессии и привязки устройств
не изменяются. Повторный запуск не перешифровывает существующие записи.
В вывод попадают только счётчики и названия недостающих групп, без паролей и хешей.

Использовать приватную резервную копию базы перед записью. Файл
`<путь-базы>.password-key` должен оставаться на постоянном приватном томе вместе
с базой и входить в её резервное копирование. Исходный JSON с паролями, заметки
и база не должны попадать в Git, публичные каталоги или аргументы командной строки.

Проверка: `node --test server/restore-passwords-test.mjs`.
