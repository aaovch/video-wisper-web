Внедрена цепочка: Python build-report → сохранённое задание → подготовка источника и HEMA-подсказок →
модельные карточки с цитатами → проверяемый импорт → статический индекс → обязательный QA.
Модель используется агентом при подготовке; сайт и обычная сборка не обращаются к модели/API.

## Проверки внедрения

- Настоящий Python CLI создал два новых отчёта из реальных кэшированных источников в пустой
  временной папке, затем прошли prepare/import, идемпотентный повтор, сохранение требования,
  изменение главы, отказ старого кандидата и пересмотренное восстановление: [lifecycle.json](lifecycle.json).
- Это проверка поисковой ветки создания отчётов, без повторной транскрибации и без правок боевых
  исходников. Старое дополнительное требование двух новых Whisper-intake не используется как
  критерий для изменения только поисковой интеграции; сами intake этим прогоном не проверены.
- Основной skill, root/web AGENTS, pipeline/publication rules и JSON CLI контракт синхронизированы.
- Python: 28 тестов; web: 73 теста прошли, 7 исследовательских штатно пропущены;
  web gate: данные, индекс, типы и production build успешны.
  Тесты временных копий из `.codex/` исключены из discovery: они раньше завышали число тестов.
- Браузер, production preview: вопрос об отдыхе между повторениями выводит «Счёт на пять» первым
  в коллекции и записи; ссылка ведёт на `sablya-10`, `#ch-2`, `t=34` для начала 33.x секунды.
  Проверены исходный текст и состояние выбранной главы; воспроизведение видео целиком не проверялось.
  В общем каталоге та же глава отображается третьей, после материалов о восстановлении.

Сложные вопросы с несколькими источниками остаются ограничением ранжирования: поиск показывает
связанные фрагменты, не обещает составленного полного ответа. Отклонённые эксперименты не включены.
Публикация не выполнялась; рабочий порядок для следующего агента — [workflow.md](workflow.md).
