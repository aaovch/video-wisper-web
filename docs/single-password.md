# Один короткий пароль на группу доступа

У каждой коллекции, записи или пакета один пароль длиной от 4 до 8 символов.
Пароль можно заменить в админке; прежний сразу теряет доступ. CLI `issue`
возвращает уже существующий пароль группы, а для новой группы создаёт пароль
из 8 символов. Личный мастер-ключ владельца остаётся отдельным серверным ключом.

Ограничение количества действует в SQLite: уникальные индексы и триггеры
исключают второй пароль как среди основных ключей, так и среди дополнительных
разрешений. Дополнительное разрешение позволяет одному ключу открывать разные
группы, сохраняя единственный пароль каждой из них.

Перед обновлением старой установки с несколькими ключами выполнить проверку:

```text
node server/consolidate-passwords.mjs <существующая-access.sqlite>
```

Сохранить приватную резервную копию базы и `.password-key`, остановить сервер,
затем применить миграцию и запустить обновлённый сервер:

```text
node server/consolidate-passwords.mjs <существующая-access.sqlite> --write
```

Миграция сохраняет самый короткий подходящий пароль каждой группы. При равной
длине выбор стабилен. Если подходящего пароля нет, создаётся новый из 8 символов.
Лишние ключи, их сессии и восстановление на устройствах отзываются. Мастер-ключ
и его сессии сохраняются. Сохранённые короткие ключи продолжают работать;
общие ключи сохраняют оставленные им группы. Все изменения и ограничения
применяются одной транзакцией. Повторный запуск не меняет уже выбранные пароли.
В отчёт попадают только счётчики, сами пароли видны только владельцу в админке.

Пароли новых записей проходят ту же проверку длины. Новый пароль публикации
должен быть доступен серверу в зашифрованном виде; одного старого хеша для
создания нового ключа недостаточно — потребуется ввести короткий пароль заново.

Проверка: `node --test server/single-password-test.mjs`.
