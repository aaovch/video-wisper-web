# Проверка качества поиска

Актуальный план развития и интеграции в основной скилл: [plan.md](plan.md).

Приоритетная проверка фехтовальных тем: [техника, тактика, упражнения и реальные коллекции](fencing/README.md).

Расширенное исследование с отложенными вопросами, E5, гибридным поиском и reranker: [глубокая проверка](deep-study.md).

Текущее внедрение: [обогащение индекса при подготовке записи](enrichment.md), 36 глав и 72 вопроса; ниже исторические результаты первого этапа, когда каталог показывал три результата. Сейчас начальная выдача содержит пять.

Дата: 2026-09-06. Индекс: 158 записей, 24 860 документов (14 261 core, 10 599 transcript).

24 синтетических вопроса по шести реальным записям, каждый в трёх областях: отдельная запись, её коллекция и весь публичный архив. Вопросы сформулированы до изменений поиска. Ожидаемые главы и цитаты из тезисов находятся в `src/lib/search-quality-cases.json`; тест проверяет, что эти основания остаются в исходных файлах.

Исполняется настоящий `searchScoped` с обоими построенными шардами MiniSearch, лимитом 120, реальными коллекциями и фильтром публичной видимости. Замок не разблокируется. Области проверяются отдельно, без автоматического расширения: иначе результат из архива мог бы скрыть провал поиска внутри записи. Расширение областей, опечатки, префиксы, пустые запросы и ограничения зон отдельно покрыты `search-core.test.ts` и `search-visibility.test.ts`.

Фрагмент — результат с ожидаемым reportSlug и chapterIndex. Карточка записи сама по себе не считается найденным ответом. Для дополнительной метрики ранга записи применяется `groupByReport`; это аналитическая группировка, а не точная копия текущего интерфейса. Главная страница показывает плоскую выдачу, сначала только три результата, и вызывает поиск с лимитом 30; scoped-поиск — с лимитом 120. MRR — среднее 1 / рангу первого ожидаемого фрагмента; отсутствие даёт 0. Полные выдачи до/после: `baseline.json` и `after.json`.

## Изменения

1. Если точное совпадение найдено только в агрегированной карточке записи, поиск дополнительно ищет главы внутри найденных записей. Раньше exact-ветка завершалась карточкой и не показывала переход к ответу. Теперь вопросы про ростковые зоны и прогрессию подъёмов на носки находят также нужный фрагмент на втором месте. Фильтры сохраняются; главы сохраняют собственный тип совпадения.
2. Для запросов длиннее трёх значимых слов исправление опечаток больше не завершает поиск отдельной выдачей. Такой вопрос проходит в ветку частичных/смысловых совпадений, которая также умеет нечёткий поиск. Короткие запросы по-прежнему получают исправление. Это устраняет преждевременную подмену темы: вопрос про монету под пальцем находит ожидаемую главу на первом месте, про иммобилизацию — в топ-5 вместо единственного результата про мобилизацию колена.

Проверялась также более жёсткая фильтрация по доле совпавших слов. Она ухудшала выдачу внутри записи, поэтому в итоговую реализацию не вошла.

## Осталось улучшить

- q11 «Сколько подходов и повторений делать детям?» — ожидаемая глава вне топ-5 коллекции и архива. Общие слова о повторениях конкурируют с контекстом детской тренировки. Следующий эксперимент: учитывать название записи при ранжировании её глав и различать «подход» как способ и как тренировочный сет.
- q22 «Почему одного успешного турнира мало для оценки работы тренера?» — ожидаемая глава на 14-м месте архива. Следующий эксперимент: повысить вес редких совместных совпадений и ограничить расширение общих слов вроде «работа», «оценка», «тренер».
- В сохранённом transcript-сниппете только первые 400 символов окна, хотя индексируется полный текст: найденное слово может не попасть в показанную цитату. Это отдельная задача качества объяснения выдачи.
- Браузерная проверка выявила эффект расширения областей: полный вопрос о прогрессии подъёмов на носки внутри записи расширяется до архива и возвращает ту же запись с нужной главой. Причина — приоритет exact в архивной карточке над локальным частичным совпадением. Короткий запрос «подъёмы на носки» остаётся внутри записи. Отдельный следующий эксперимент — не расширять область ради агрегированной карточки текущей записи; текущий контракт fallback в этом изменении сохранён.
- На главной странице вопрос про иммобилизацию после исправления находит главу «Три сценария программы» на четвёртом месте, под кнопкой «Показать все». Топ-5 движка ещё не означает видимость ответа без дополнительного клика; следующий UI-эксперимент — показывать пять результатов сразу и измерять топ-3 отдельно.
- Для сравнения с векторным/гибридным поиском сначала расширить разметку релевантности и добавить отложенный набор вопросов. Текущий набор использовался при исправлении алгоритма и не является независимым подтверждением обобщения.

Это пилот по шести записям, а не оценка всех 158. Для вопроса размечены известные подходящие главы; другие записи тоже могут содержать правильный ответ. Отсутствие ожидаемой записи не доказывает бесполезность всей выдачи. Набор не измеряет медицинскую/предметную истинность исходных тезисов, сетевую задержку, качество поиска без общих слов и все состояния интерфейса.


`npm test` также перестраивает индекс и запускает этот набор. Для каждого успешного сценария закреплён топ-5; три известных промаха перечислены явно и продолжают входить в метрики. Отдельно закреплены нижние границы попаданий записи в топ-3. При добавлении контента разбирать ухудшения по выдаче и источникам, не снижать пороги автоматически.
