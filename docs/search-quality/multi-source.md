# Составные вопросы: диагностика кандидатов

Проверены 12 уже раскрытых вопросов с двумя ожидаемыми главами и 297 обычных сценариев из текущих пилотных результатов. Источники и оценки не менялись. Это диагностика на известных вопросах, не новый holdout.

## Перестановка сохранённой первой десятки

| Вариант | Обычные Hit@5 | Потери Hit@5 | Среднее покрытие составных вопросов |
|---|---:|---:|---:|
| Текущий | 220/297 | 0 | 45,8% |
| Главы раньше обзоров и материалов | 226/297 | 0 | 45,8% |
| Не более двух результатов записи сначала | 207/297 | 13 | 45,8% |
| Оба изменения | 216/297 | 10 | 45,8% |

Точное и префиксное совпадения не переставлялись. Перестановка глав — кандидат для отдельного исследования, но она не решила задачу нескольких источников. Ограничение по записи не принимается из-за потерь. Неразмеченные материалы не считаются неверными: текущая метрика ищет конкретные подтверждённые главы.

В каждом составном вопросе число ожидаемых глав в сохранённой десятке равно их числу в первой пятёрке: недостающий источник нельзя поднять простой перестановкой этих кандидатов.

## Проверка глубины поиска

В runtime найден отдельный предел семантической выдачи: 8 результатов внутри записи и 16 снаружи, даже если вызывающий код просит больше. Для диагностики добавлен выключенный по умолчанию `VITE_SEARCH_CANDIDATE_LIMIT`; он позволяет исследовать до 120 кандидатов, не меняя обычные пределы.

На тех же 12 вопросах расширение с 16 до 120 результатов подняло доступность ожидаемых фрагментов с 11/24 до 14/24 (45,8% → 58,3%). Покрытие первой пятёрки осталось 11/24. Ещё десять ожидаемых фрагментов не попали даже в расширенную выдачу; это не доказывает их отсутствие во всём сыром индексе.

**Решение:** рабочее ранжирование и лимиты сохранены. Большой лимит сам по себе не улучшает показываемые результаты, а ограничение по записи ухудшает обычные запросы. Следующий эксперимент должен отдельно проверить извлечение по частям составного вопроса, а затем объединение найденных глав. До нового независимого прогона и регрессий включать такую конфигурацию нельзя.

Вопросы по-прежнему возвращают фрагменты источников, не готовый ответ. Оценка достаточности и альтернативных полезных материалов ещё не завершена; процент уверенности в интерфейс не добавлялся.

Артефакты: [перестановки](multi-source-diagnostic.json), [глубина кандидатов](multi-source-candidates.json). Команды:

```powershell
node scripts/search-enrichment/multi-source-diagnostic.mjs
$env:MULTI_SEARCH_DIAGNOSTIC='1'
node node_modules/vitest/vitest.mjs run scripts/search-enrichment/multi-source-candidates.test.ts --pool=threads --maxWorkers=1 --no-file-parallelism
Remove-Item Env:MULTI_SEARCH_DIAGNOSTIC
```

Продолжение: [эксперимент поиска по частям вопроса](query-parts.md) завершён. Автоматическое разбиение и объединение не приняты; рабочие пределы и ранжирование сохранены.
