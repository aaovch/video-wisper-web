# Обогащение поиска при подготовке записи

Продолжение с приоритетом на фехтование: [пять коллекций, дополнительные 55 глав и отдельные проверочные вопросы](fencing/README.md). Ниже сохранены результаты первого пилота по AI и биоэнергетике.

Внедрён пилот LLM-обогащения: 36 глав двух записей, 36 пояснений и 72 возможных вопроса. Контент подготовлен Codex по исходным заголовкам, summary и theses. Модель не запускается в браузере, при запросе пользователя или при сборке сайта. API, ключи и отдельный сервер не нужны. Пилот включён в локальную сборку; публикация отдельно.

## Что хранится и как ищется

`src/lib/data/search-enrichment/<slug>.json` — версионируемый sidecar: версия схемы и промпта, сведения об авторе/генераторе, индекс главы, SHA-256 источника, контекст и вопросы с цитатами-основаниями. Поле `sourceHash` включает название записи и полный объект главы. Никакие исходные отчёты и транскрипты ради поисковых формулировок не меняются.

Сборщик добавляет `field_context` и `field_questions` только в документ главы. MiniSearch использует их при поиске похожих фрагментов с весами 0.65 и 0.8. Точное совпадение, префикс и исправление опечаток используют только исходные поля. Сниппет, название, ссылка и таймкод остаются исходными. Фильтры областей и видимости применяются до ранжирования, как раньше. Синтетические формулировки не выдаются за цитаты.

Каталог теперь сразу показывает пять результатов, как scoped-поиск, чтобы четвёртый и пятый найденные фрагменты были видны без дополнительного раскрытия.

Нет sidecar — работает обычный поиск. Устаревший или некорректный sidecar — сборка останавливается с указанием проблемы; обновить метаданные или осознанно удалить соответствующий sidecar. Автоматическая проверка подтверждает наличие цитаты, но **не доказывает**, что она логически обосновывает формулировку: агент должен проверить смысл, отрицания и оговорки.

## Подготовка следующей записи

Из корня `video-wisper-web`, после окончательной редакции смысловых глав:

```powershell
node scripts/search-enrichment/cli.mjs prepare <slug> --dry-run
node scripts/search-enrichment/cli.mjs prepare <slug>
```

Оба вызова возвращают JSON с `ok`, `artifacts[]` и числом глав. Второй сохраняет `.codex/search-enrichment/<slug>.request.json`. Агент читает этот пакет, выполняет содержащийся в нём промпт и сохраняет candidate JSON. Не передавать генератору оценочные запросы. На главу: короткое пояснение и 1–5 разных вопросов, на которые действительно отвечает источник, с точными цитатами. Указать фактического генератора. Текущий workflow выполняется агентом; unattended API-генерация не реализована.

```powershell
node scripts/search-enrichment/cli.mjs import <slug> <candidate.json> --dry-run
node scripts/search-enrichment/cli.mjs import <slug> <candidate.json>
npm test
npm run check
npm run build
```

Проверять exit code и `ok`. Сборка детерминирована относительно файлов, не вызывает модель. Дополнения можно рецензировать в Git отдельно от текста записи. При изменении главы повторно подготовить затронутые данные; импорт допускает частичный список глав, но заменяет sidecar целиком — сохранить неизменившиеся валидные entries при частичном обновлении.

## Результаты пилота

Сравнение настоящего `searchScoped` с удалением повторов, как в интерфейсе: 114 формулировок, 330 сценариев. В каждой области 108 запросов с известным ответом; ещё 6 отрицательных проверяются по архиву. Запросы включают связанные варианты с опечатками и перефразировками, поэтому это не 108 независимых наблюдений.

| Область | Нужная глава в первых 3: до → после | В первых 5: до → после |
|---|---:|---:|
| Запись | 90 → 92 / 108 | 91 → 94 / 108 |
| Коллекция | 78 → 83 / 108 | 83 → 87 / 108 |
| Архив | 66 → 70 / 108 | 73 → 78 / 108 |

В измеренном наборе 15 сценариев улучшили позицию ожидаемой главы, ухудшений этой позиции нет. Например, «Чем инженерия контекста отличается от написания промпта?» раньше не находил ожидаемую главу в возвращённом списке, теперь она первая внутри записи и третья по архиву. «Энергосистемы включаются по очереди или работают вместе?» поднялся с 13-го на 4-е место по архиву.

Отрицательные запросы: 5 из 6 по-прежнему дают постороннюю выдачу. Это нерешённая проблема отсечения слабых совпадений. Пилот охватывает только 36 из 2572 публичных глав и не доказывает выигрыш на всём архиве или реальном трафике. Автор видел прежние оценки; тесты не являются новым независимым holdout. Оценочные вопросы не копировались в метаданные. Отдельной человеческой разметки нет.

Изолированный эксперимент с индексом цельных глав: на 13 вариантах запросов к пилотным главам архивный Hit@3 = 5/13 без дополнений, 7/13 с контекстом, 8/13 с контекстом и вопросами. Это **другая** архитектура ранжирования, её числа нельзя подменять числами сайта. Остальные 95 запросов сохранили Hit@3. Размер этого индекса вырос с 1 481 204 до 1 492 191 байт; основное ядро сайта — примерно с 7.08 до 7.10 MiB.

Машиночитаемые результаты: [абляция глав](enrichment-pilot/results.json), [поиск сайта и изменившиеся позиции](enrichment-pilot/runtime.json). Полные локальные выдачи: `.codex/search-enrichment/evaluation.json` и `.codex/search-lab/tasks.json`.

## Воспроизведение

```powershell
npm run test:search-lab
npm run test:search-enrichment
```

Первая команда строит текущий индекс и оценивает 330 сценариев; вторая сравнивает три варианта обогащения и отказывается использовать устаревший корпус. Нейросетевые результаты прежних запусков не примешиваются в lexical-only прогон.

Для чистого сравнения настоящего сайта выполнить два прогона на одной версии кода и данных:

```powershell
$env:SEARCH_ENRICHMENT = '0'
$env:SEARCH_LAB_DIR = '.codex/enrichment-off'
npm run test:search-lab
Remove-Item Env:SEARCH_ENRICHMENT
$env:SEARCH_LAB_DIR = '.codex/enrichment-on'
npm run test:search-lab
Remove-Item Env:SEARCH_LAB_DIR
node scripts/search-enrichment/compare-runtime.mjs .codex/enrichment-off/tasks.json .codex/enrichment-on/tasks.json
```

Последняя команда проверяет идентичность вопросов, областей и ожидаемых глав. Для следующего расширения корпуса нужны новые вопросы, написанные после фиксации дополнений без чтения сгенерированных формулировок, больше отрицательных примеров, запросы к деталям только из транскрипта и проверка смысловой обоснованности дополнений человеком.

Проверка реализации: 40 обычных тестов прошли; отдельный lab выполнил 330 сценариев; type-check без ошибок и предупреждений; production build успешен; проверка индекса всех 158 записей успешна. После проверки точного legacy API отдельно повторно прошли 24 теста ядра/устойчивости. В браузере локальной production-сборки подтверждены исходные сниппеты и таймкоды внутри записи и коллекции, пять начальных результатов каталога и видимость главы «Три системы работают одновременно». Ошибок консоли при финальной проверке каталога нет. Мобильное устройство и медленная сеть в этом этапе не тестировались.

Подходы: [Doc2Query](https://github.com/castorini/docTTTTTquery), [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval), [фильтрация неудачных дополнений](https://arxiv.org/abs/2301.03266). Реализовано текстовое обогащение индекса; это не полная реализация их нейросетевых поисковых систем.
